# Automations

An automation is a flow you draw on a canvas: a trigger ("when this happens") wired to steps ("do these things"). Once it's on, it runs by itself on the server. Open **Automation** in the navigation rail; if it isn't there, automations aren't enabled for your organization.

Viewing, building, testing and switching flows on are separate permissions; a missing button means your role lacks it.

- [Build a flow](/docs/use/automations/build-a-flow): create an automation and wire its steps together.
- [Choose a trigger](/docs/use/automations/choose-a-trigger): start a flow from an event, a record change, a schedule, a web request, or by hand.
- [Use values from earlier steps](/docs/use/automations/use-values-from-earlier-steps): fill a step's fields from the trigger or a previous step.
- [Branch, loop or pause a flow](/docs/use/automations/branch-loop-or-pause-a-flow): take different paths, repeat steps for a list, wait, or handle a failure.
- [Test a flow](/docs/use/automations/test-a-flow): run it once and see what each step did.
- [Turn a flow on or off](/docs/use/automations/turn-a-flow-on-or-off): let it run by itself, pause it, or delete it.
- [Check past runs](/docs/use/automations/check-past-runs): see whether recent runs succeeded and where one failed.

Every node and its fields are listed in [Automation nodes](/docs/reference/automation-nodes). How runs work behind the scenes is in [How automations run](/docs/concepts/automations).
